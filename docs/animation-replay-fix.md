# 動畫排程修正（2026-10-25）

## 問題與行為

scheduleReplay 使用 4000ms 的積壓播放窗口，與 replayOffset 的 1500ms 上限不一致。
在 now=5000、事件原定時間為 0/2000/4000 的案例，最後事件排在 9000，超過原測試要求的 6500。
現改為共用 REPLAY_MAX_AHEAD_MS=1500，保留短間隔，壓縮長積壓與過遠的未播放事件；原失敗斷言未放寬。

- 新舊事件在同一共用佇列排程，seq 去重，排序仍依時間及序號。
- 只壓縮尚未發射事件；已發射箭矢的 200ms 命中期限不因新封包而改變。
- 既有三重矢即時播放與 70ms 間隔、命中才扣血／跳字、MISS、死亡及掉落順序維持原規則。
- 怪物出生／技能後尚有攻擊排隊時，新攻擊加入隊尾，不再超車或重新啟動當前動作。
- 切入背景或 rAF 中斷超過 6 秒，清除舊視覺佇列並還原最新已確認的角色／怪物狀態，不重播歷史攻擊。

1500ms 為未發射事件的排程窗口，並非瀏覽器休眠或主執行緒阻塞時的牆鐘時間保證。
飛行及粒子仍有各自壽命，不以大量 setTimeout 強制同時建立所有效果。
