# One swing, one normal hit

Each confirmed server normal attack now carries `attackId = characterId:eventSeq`.
The value is generated by the existing authoritative attack timer, and survives
retransmission. Skill/proc/pet damage is not reassigned to a normal swing.

The motion hook passes its captured swing start token to the contact registry.
Once that token has issued a contact permit, further frame callbacks for the same
token cannot issue another, including callbacks with a different monster UID.
The next swing has a different token and can hit normally.

The registry remembers completed normal event sequences (bounded to 512, versus
160 server-retained events), so retransmissions neither requeue an old target nor
consume the next real swing's permit. The view records normal attack receipts,
also bounded to 512. One attack ID can apply HP and damage numbers only once
across targets/frames. Legacy events use their sequence number. Bow launch and
impact have separate receipts: launch does not prematurely apply HP.

This is not a global monster invulnerability timer. Actual attack speed and
independent skill/proc damage retain their existing rules. It adds duplicate
protection; it is not proof that all symptoms in the supplied recording have the
same cause. Mobile runtime verification remains outstanding.
